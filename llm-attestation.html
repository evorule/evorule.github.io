对 AI 的每一次调用，我们存证到哪一级

这不是一份营销页。它逐条说明 evo-agent 对 LLM 活动——每次模型调用的发送、返回、组装全过程——的存证做到了什么、哪些尚未覆盖、为什么这样取舍。已做到的附验证方法，未做到的写明原因。

第一级 · 内容全文级 — 已实现 第二级 · 发送字节级 — 已实现 第三级 · 线路字节级 — 未建（如实标注）

三级存证标尺

"字节级存证"不是开关，是一条按捕获点分层的递进标尺。越往下越接近"线上真实发生的字节"。

第一级

内容全文级

✓ 已实现

发给模型的消息全文与模型返回的全文，逐字写入防篡改哈希链。无抽样、无日志级别过滤、无长度截断；摘要类辅助调用同样入链，不存在绕开审计的出站路径。

回答："当时到底发了什么、模型到底回了什么？"
第二级

发送字节级

✓ 已实现

发送内容的确定性序列化字节（消息集合＋核心生成参数）的哈希，在发送时刻入链。任何人可用链上材料重建发送内容并重算哈希比对；裁剪边界（裁了多少条）同时在账。

回答："事后重建的发送内容，与当时实际发送的一致吗？"
第三级

线路字节级

✗ 未建 · 如实标注

网络线路上实际传输的原始字节（含提供商自己的序列化细节、流式帧序）的哈希。捕获点不在本进程（TLS 在独立执行体终结）——补法已定，按真实争议场景投入，不做无时间表的承诺。

将回答："提供商线上实际返回的原始字节是什么？"

什么能检出，什么不能

七类攻击的覆盖现状——包括两行我们不覆盖的。诚实标注比全绿更有价值。

攻击结果依赖
篡改链上记录内容（改一条消息 / 回答）✓ 检出哈希链断裂即红
隐瞒一次模型调用（"影子调用"）✓ 已归零全路径经审计协议＋双账本对账
事后伪造"当时发送的内容"✓ 检出重建哈希 ≠ 发送时刻存证哈希
篡改存证记录本身✓ 检出存证与业务事实同链
整链重算伪造（内容改完重算全部哈希）✓ 检出签名锚点绑定失败
流式聚合过程出错或被替换（"模型说的" ≠ "交付的"）✗ 未覆盖属第三级——见上方边界
与提供商的内容纠纷（"模型实际返回 X 不是 Y"）△ 可追责凭请求追踪标识对质；不可密码学证明

诚实边界

这些是当前的真实边界，不是疏忽，是写明的取舍。

存证哈希域未含全部请求参数

发送存证的哈希覆盖 模型名＋温度＋消息集合；同样影响生成结果的 max_tokens、工具定义等参数未入哈希域——已知边界，列为收紧候选，不以"发送字节级"四字掩盖。

提供商真实性不可证明

主流模型 API 不对响应签名。存证只能绑定"我们收到了什么"，不能证明"对方发出了什么"。争议时可凭请求追踪标识向提供商对质——追责可以，证明不行。

流式聚合是信任点

"多个流式增量 → 最终整包"的变换在独立执行体内完成，其正确性当前靠代码审查与版本记录，不靠密码学绑定。第三级建成后双端哈希锁定此变换。

时间戳不参与哈希

时间是非确定性字段，不进任何哈希域；时序争议由链上顺序与签名锚点的时间承载。引擎短暂不可达时存证降级告警，本地全文账本始终独立在账。

取舍原则

  1. 哈希可以旅行，字节不必——捕获点本地算哈希、哈希入链；原始字节不默认上链（体积、隐私、成本）。
  2. 存证与留存分层——链上存哈希与元数据（轻、可验、永久），本地账本存全文（重、可对账），两者各有独立哈希链互为印证。
  3. 不建新链——新证据类型一律走既有哈希链，自动被锚点、哨兵、公开证据投影覆盖；多一条链就多一处分叉与对账成本。
  4. 边界先于路线——未覆盖的能力先写进边界再谈路线，不拿计划中的能力充当现有能力，不做无时间表的承诺。
  5. 按真实争议场景投入——第三级的增量集中在外部纠纷与合规要求；场景真实出现前，投入属于过度工程。

自己验

不需要安装 evo-agent——一个 Python 脚本加一个 blake3 库，离线验完。

# 导出证据文档（evo-agent 侧）
evid_export --journal data/sessions/{id}.jsonl -o evidence.json

# 验证（任何第三方；单文件验证器）
pip install blake3
python evid_verify.py evidence.json                  # 链完整性，篡改六分类定位
python evid_verify.py evidence.json --pubkey <hex>   # ＋ Ed25519 签名验证

验证器自带自检（python evid_verify.py --self-test，4/4 通过方可信）；跨语言哈希契约由黄金向量双向锁定并常驻 CI——不靠注释宣称兼容。
