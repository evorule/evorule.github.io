EVID · 原创设计

故意丢弃密钥的证据链

大多数密码学体系想尽办法把密钥守住；EVID 的第一步设计决策，是把密钥扔掉。这一扔，换来了任何第三方零依赖跨语言可验的公开证据——也换来一条必须写进基因的铁律。

无密钥 · 公开可验 单文件验证器 字节级契约 · 双向锁定 七连破坏注入 · CI 常驻

一第一个决策：把密钥扔掉

一条证据链要"公开可验"，直觉的做法是：保留签名，把公钥一起发布，谁都能验签。我们没有这样做。EVID 投影层不含任何密钥——证据文档里只有无密钥的内容哈希链，每一环是前七字段因果元组的 BLAKE3 哈希，任何人拿到文档都能逐环重算。

因为"验签"这道门槛比看上去高：验证方需要理解签名体系、需要正确的公钥、需要信任公钥的分发渠道。而重算一条无密钥的哈希链，只需要哈希函数本身——一个 Python 单文件脚本加一个 blake3 库，离线、断网、不装任何本系统软件，十分钟验完整条证据链。

密钥换公开性：扔掉密钥的所得，是"任何第三方、零依赖、跨语言"这六个字；所失，是下一节。

二由此推出的铁律

扔掉密钥的直接后果：任何人都能构造一条合法的伪造 EVID 链。

EVID 永远不能单独作为"执行确实发生过"的证据。它必须与签名锚点联用——三层各司其职，缺一不可。
层证明什么凭什么
事实哈希链内部自洽逐环链接，改任何一环即断
签名锚点链来源可信Ed25519 签名——无私钥造不出能通过绑定的假锚
EVID 投影公开可验无密钥、标准格式、单文件验证器

一个类比：哈希链是账本本身，签名锚点是盖章，EVID 是任何人都能拿去对光的复印件——复印件可以伪造，所以复印件上的章（锚点绑定）才是关键；而验复印件真伪不需要到我们柜台，这正是复印件存在的意义。

三两代收敛：完整设计与假兼容

这个理念经历两代独立演进。第一代设计完整却从未接线；其声称的跨语言兼容经实测为假——两种语言算出不同的值。从那天起立下规矩：跨语言兼容不靠声明，靠对拍。

第二代不是移植，是在已验证的三层审计体系之上重建。第一代的教训逐条变成防线：

第一代的坑第二代的防线
布尔/整数编码分裂七字段全部字符串化或显式 null
域判定整链一个常量、非域事实虚设值逐记录取真实值，无则 null——参与哈希但不造假
规则身份硬编码进哈希域不重复存身份——fact_hash 回溯原链
三套状态哈希排除集各不相同不重复算状态哈希——事实链自身承载因果
签名可移植到不同长度的链签名载荷覆盖链长度——短链签名冒充长链不可通过
删尾攻击无专项检出tail_truncated 专项分类
同密钥换链内容不可区分chain_substituted 专项分类
一个从未被触发的篡改分类占着位置删掉，不继承——没有实测支撑的分类是装饰

四先定义后实现：字节级契约

施工顺序是刻意的：先写死哈希契约的字节级定义，再写实现。

evid_hash = BLAKE3( canonical_json([
    str(seq),            // 序号——十进制字符串
    step_id,             // 步骤标识
    fact_type,           // 事实类型
    cause | null,        // 因果前驱
    previous_evid,       // 前条哈希（空=创世）
    fact_hash,           // 原始审计链内容哈希
    domain_check | null  // 域判定
]))

契约的锁定方式是双向的：五组黄金向量加创世根，由 Python 独立推导出期望值，Rust 测试逐值断言。不是 Rust 算完 Python 抄一遍——是两边各自从契约文本独立走到数值，在中间碰头。任一实现漂移，CI 即红。

五验收门前置：让破坏在施工期就发生

七连破坏注入：改字段、删中间记录、插入记录、删尾、整链重算+旧签名、同密钥不同链、验证器自检——逐项断言退出码与篡改分类。

这扇门在施工期就咬人了：首轮实跑 8 项中 3 项不达标——序号错位检查抢先短路吞掉了"删记录/插记录"的精确分类；链替换精化发生在结果打印之后（改了标签没人看得见）；删尾时把必然伴随的根失配与删尾本身重复报告。三处都是真缺陷，当场修复后 8/8 全过，并成为 CI 常驻步骤。

这件事强化了一条工程信念：验收门的价值在于它开在施工期里，而不是施工期外。等上线后再注入，同一批缺陷就是三个事故报告。

六它在体系中的位置

签名锚点链（防抵赖 · 密钥层）
Ed25519 · 链头绑定 · 密钥不落审计资产
事实哈希链（防篡改 · 内部层）
BLAKE3 · 逐条链接 · write-ahead · 崩溃恢复
EVID 公开投影（公开可验层）
无密钥 · 标准格式 · 单文件验证器 · chain_root ← 锚点签名绑定
运行时哨兵 + 跨语言对拍（互证层）
基线比对 · 黄金向量 · CI 强制对拍

EVID 不替代任何一层。它是审计链的公开面——把"内部可信"翻译成"公开可验"。内部三层解决"账是真的"；EVID 解决"外人也能查这本账"，而不需要成为外人也能改的账。

七诚实边界

伪造 EVID 链可构造

设计使然，代价公开记账。防护=签名锚点联用（第二节铁律）。

验证器自身需要被信任吗？

不需要——自带四项自检（有效链通过/篡改链拒绝/确定性/删尾检测），哈希契约由黄金向量双向锁定；不放心可用任何语言按契约自写，二十行。

时间戳不参与哈希

时间非确定；证据文档创建时间从链尾记录派生（同输入同输出），不取验证时的时钟。

不做的三件事

不重做内部哈希链（投影引用不重算）；不新定编码规范（沿用全站契约）；不建独立信任根（信任归锚点层）。

八亲手验

# 导出证据文档
evid_export --journal data/sessions/{id}.jsonl -o evidence.json

# 验证（任何第三方）
pip install blake3
python evid_verify.py evidence.json                 # 链完整性（篡改六分类）
python evid_verify.py evidence.json --pubkey <hex>  # + Ed25519 验签（长度防移植）
python evid_verify.py --self-test                   # 验证器自检 4/4
